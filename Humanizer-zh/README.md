## 本仓库的本地修订

本仓库以用户确认的中文适配和行为修订为准。同步上游时逐项合并适用改动；发生冲突时优先保留本地约定，并保留上游来源和许可证。

本地修订将 24 种模式与示例移到 [references/patterns.md](references/patterns.md)，按任务需要查阅；默认依据 [SKILL.md](SKILL.md) 中的编辑原则处理。修订后的行为包括：

- 保留原文事实和作者语气，纠正示例中凭空增加来源、数字、经历和反馈的问题。
- 根据语境处理列表数量、标点和句式；技术及事实性文本保持中立。
- 仅用于润色或专项审阅表达问题；一般阅读、事实核查和逻辑审查不单独触发。
- 默认交付最终文本，只读表达审阅只给建议，按用户要求提供对照和说明。
- 英文标题大小写和引号模式仅说明适用边界，不机械套用到中文。
- 取消默认主观评分和固定工具名称限制，使用目标智能体实际提供的能力。

下方安装命令指向上游。如需安装本仓库的修订版，请按仓库根目录 README 的说明安装 `erning/agent-skills` 中的 `humanizer-zh`，并保留完整技能目录及参考文件。

## 项目简介

Humanizer-zh 用于润色中文表达，减少套话、夸张表述和机械句式，保留事实与作者语气。文本是否由 AI 生成不决定是否使用，也不能仅凭这些写作模式判断作者身份。

本项目适用于：

- 直接润色中文文章、说明或个人文本。
- 专项审阅表达是否空泛、夸张或机械，只报告问题和建议。
- 在有具体表达问题时，按需查阅相关模式与示例。

仅阅读、总结、提取信息、核查事实、审查逻辑、修正标点排版或专业术语时，不使用本 skill。要求只审阅时不修改原文；要求改写时直接交付改稿。

## 安装

### 方法一：通过 npx 一键安装（推荐）

```bash
npx skills add https://github.com/op7418/Humanizer-zh.git
```

这是最简单的安装方式，会自动将技能安装到正确的目录。

### 方法二：通过 Git 克隆

```bash
# 克隆到 Claude Code 的 skills 目录
git clone https://github.com/op7418/Humanizer-zh.git ~/.claude/skills/humanizer-zh
```

### 方法三：手动安装

1. 下载本项目的 ZIP 文件或克隆到本地
2. 将 `Humanizer-zh` 文件夹复制到 Claude Code 的 skills 目录：
   - **macOS/Linux**: `~/.claude/skills/`
   - **Windows**: `%USERPROFILE%\.claude\skills\`

3. 确保文件夹结构如下：
   ```
   ~/.claude/skills/humanizer-zh/
   ├── SKILL.md       # 技能定义文件（中文版）
   ├── README.md      # 说明文档
   └── references/
       └── patterns.md # 按需查阅的模式与示例
   ```

### 验证安装

重启 Claude Code 或重新加载 skills 后，在对话中输入：

```
/humanizer-zh
```

如果安装成功，该技能将被激活。

## 使用

### 基础用法

在 Claude Code 中，你可以通过以下方式使用 Humanizer：

#### 1. 直接调用技能

```
/humanizer-zh 请帮我人性化以下文本：

[粘贴你的 AI 生成文本]
```

#### 2. 在对话中使用

```
请用 humanizer 帮我改写这段话，让它更自然：

这个项目作为我们团队致力于创新的证明。此外，它展示了我们在不断演变的技术格局中的关键作用。
```

#### 3. 处理文件内容

```
/humanizer-zh 请人性化 article.md 文件中的内容
```

### 使用场景示例

#### 场景 1：改写营销文案

**输入：**
```
/humanizer-zh
坐落在风景如画的杭州市中心，这家咖啡馆拥有丰富的文化底蕴和令人叹为观止的装饰。它作为城市咖啡文化的焦点，为顾客提供无缝、直观和充满活力的体验。
```

**输出示例：**
> 这家咖啡馆位于杭州市中心。

原文未提供经营年限、咖啡种类或建筑来源，改写时不添加这些信息。

#### 场景 2：改写学术摘要

**输入：**
```
/humanizer-zh
本研究深入探讨了机器学习在医疗诊断中的关键作用，突出了其在不断演变的医疗格局中的重要性。此外，它为该领域的未来发展奠定了坚实的基础。
```

**输出示例：**
> 本研究分析了机器学习在医疗诊断中的应用。

具体疾病、时间范围和样本数量需要由原文提供。

#### 场景 3：改写博客文章

**输入：**
```
/humanizer-zh
人工智能不仅仅是一种技术，它是我们思考未来的方式的革命。行业专家认为这将对整个社会产生持久影响。
```

**输出示例：**
> 人工智能正在改变我们思考未来的方式。

原文没有提供具体专家或个人经历，不补写来源和聊天故事。

## 参考的写作模式

保留上游 **24 种**模式的编号，按下列四组查阅。它们是表达检查的线索，不是词语禁用表或判断文本来源的证据。

### 📝 内容模式（6种）
1. 过度强调意义、遗产和更广泛的趋势
2. 过度强调知名度和媒体报道
3. 句末附加的空泛分析
4. 宣传和广告式语言
5. 模糊归因和含糊措辞
6. 提纲式的"挑战与未来展望"部分

### 🔤 语言和语法模式（6种）
7. 过度使用的"AI 词汇"
8. 避免使用"是"（系动词回避）
9. 否定式排比
10. 三段式法则过度使用
11. 刻意换词（同义词循环）
12. 虚假范围

### 🎨 风格模式（6种）
13. 破折号过度使用
14. 粗体过度使用
15. 内联标题垂直列表
16. 英文标题大小写的适用边界
17. 表情符号
18. 引号样式的适用边界

### 💬 交流模式和填充词（6种）
19. 协作交流痕迹
20. 知识截止日期免责声明
21. 谄媚/卑躬屈膝的语气
22. 填充短语
23. 过度限定
24. 通用积极结论

## 手动使用方法

先判断任务是否要求润色或专项检查表达，再按请求选择直接改稿或只报告问题。需要具体例子时，按主题检索参考文件。交付前对照原文检查事实、限定条件、作者立场和技术内容。

个人写作可以保留原有观点、幽默和感受，技术和事实性文本保持中立。无需为了显得自然而新增第一人称、制造生活经历，或强行改变句子和列表的数量。

例如，面对没有具体功能信息的软件更新文案，可以改写为：

> 软件更新旨在改善用户体验，提高使用效率。

只有原文或用户给出了具体功能、测量结果或用户反馈，才能加入相应细节。

## 常见 AI 词汇警示列表

以下词汇可用于查找空泛或重复表述，正常用法应保留，不能按词表机械删除：

- 此外、至关重要、深入探讨、强调
- 持久的、增强、培养、获得
- 突出、相互作用、复杂/复杂性
- 格局（抽象名词）、关键性的、展示
- 织锦（抽象名词）、证明、强调
- 宝贵的、充满活力的
