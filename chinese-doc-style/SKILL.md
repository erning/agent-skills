# 中文正式文档写作规范

在创建或直接修改正式中文文档时统一书写格式。规范化应服务于阅读，不应改变原意，
也不应破坏技术内容。

## 工作流程

1. 确认用户需要新建文档、改写正文，还是直接修正文档格式。
2. 识别并保护代码、命令、URL、路径、版本号和标识符。
3. 完成内容写作或修改，再统一词汇、空格、标点、大小写和地区用词。
4. 通读结果，确认含义、Markdown 结构和技术内容保持正确。
5. 直接交付新建或修改后的完整文本或文件。

## 核心检查

- 默认使用简体中文和中国大陆常用词，现有文档另有约定时保持原风格。
- 品牌、产品、项目和技术名称使用官方大小写；无法确认时保留原文。
- 中文与英文、中文与数字、数字与拉丁字母单位之间通常保留一个半角空格。
- 中文或以中文为主的句子使用全角中文标点，完整英文句子使用英文标点。
- 不要机械拆分日期、时间、版本号、小数、百分比、比例、端口号或文件名。
- 保留原有标题层级、列表、表格、代码块和链接目标，除非用户明确要求调整。

## 保护技术内容

默认不修改以下内容内部的字符：

- 围栏代码块和行内代码
- Shell 命令、参数和环境变量
- URL、电子邮件地址和 Markdown 链接目标
- 文件路径、文件名、Git 分支名和版本号
- API 名称以及函数、类、变量等代码标识符
- 用户要求保留的引用或原文

可以调整这些内容与中文正文之间的空格。Markdown 链接的可见文字属于正文，链接
目标必须保持不变。

## 输出方式

- 用户提供文本时，直接返回修改后的完整文本。
- 用户要求编辑文件时，直接修改文件，不额外生成副本。
- 只说明有实际价值的内容变化，不逐条解释重复的机械格式修正。
- 遇到不确定的术语、品牌写法或标识符时，保留原文并简要指出疑点。

## 详细规范

默认只使用上述核心检查，不要加载额外参考。仅当用户明确要求严格、逐项的发布前
修订，或遇到无法依据核心检查判断的规则冲突时，读取 `references/style-guide.md`。

若任务还要求改变写作风格、语气或去除 AI 写作痕迹，先完成内容层面的修改，最后再
执行本规范的格式检查。
