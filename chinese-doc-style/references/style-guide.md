# 中文文档详细格式规范

本文件补充 `SKILL.md` 中的核心检查，仅在严格、逐项的格式检查（直接修订或只读审阅），或遇到规则冲突时读取。只读审阅只报告问题和建议，不据此修改文件。

## 词汇与专有名词

### 选择明确、简洁的表达

在中文和英文之间，选择读者最容易理解且最简洁的说法。已经广泛使用的英文专名或缩写不必生硬翻译。

正确：

> NBA

不建议：

> 北美职业篮球联赛

### 使用官方大小写

品牌、产品、项目和技术名称使用其官方写法。无法确认时，不要仅凭常见拼写自行改动。

正确：

> 使用 GitHub 登录。

错误：

> 使用 Github 登录。
>
> 使用 github 登录。

## 空格

### 中文与英文之间增加空格

中文和拉丁字母组成的英文单词、缩写或专有名词之间增加一个半角空格。

正确：

> 本站点使用 Jekyll 搭建，应用 HPSTR 主题。文章保存在 `_posts` 目录下。

错误：

> 本站点使用Jekyll搭建，应用HPSTR主题。文章保存在`_posts`目录下。

### 中文与数字之间增加空格

中文和阿拉伯数字之间增加一个半角空格。

正确：

> 今天买菜花了 5000 元。

错误：

> 今天买菜花了5000元。

### 数字与单位之间增加空格

数字与中文量词或使用拉丁字母表示的单位之间增加一个半角空格。

正确：

> 我家的带宽是 1 Gbps，硬盘容量是 10 TB。

错误：

> 我家的带宽是 1Gbps，硬盘容量是 10TB。

不要机械拆分日期、时间、版本号、小数、百分比、比例、端口号、文件名或代码中的数字，例如 `2026-06-09`、`v2.1.0`、`3.14`、`50%`、`16:9` 和 `localhost:3000`。用户或项目已有单位约定时，优先保持其一致性。

### 避免多余空格

- 中文标点前后通常不加空格。
- 行首、行尾不保留无意义的空格。
- 不要在 Markdown 标记内部随意加空格。
- 不要为了中英文间距破坏行内代码、链接或强调语法。

## 段落与源码换行

- 中文正文按语义分段，每个段落在 Markdown 源码中写成一行，不为满足固定列宽主动换行；列表项中的每个正文段落也按此处理。
- 长行由编辑器自动折行显示。不要在相邻中文字符之间插入源码换行，避免渲染后出现额外空白。
- 合并同一段落中的换行时，中文字符之间不补空格；中英文、数字、行内代码和链接边界保留实际需要的空格。
- 保留段落间的空行、标题、列表项、嵌套层级、表格行和代码块，以及用户明确要求的诗行、地址等有意换行。不要把整篇文档压成一行。
- 代码、命令和其他需要逐字保留的内容按其自身格式处理，不套用中文正文的换行规则。

## 标点符号

### 中文句子使用全角中文标点

中文句子以及以中文为主的中英文混排句子使用全角中文标点，包括：

```text
，。！？：；（）“”《》、「」
```

正确：

> 核磁共振成像（NMRI）是什么原理？JFGI！

错误：

> 核磁共振成像(NMRI)是什么原理?JFGI!

### 完整英文句子使用英文标点

嵌入中文段落的完整英文句子使用半角英文标点。包裹该句的中文引号仍使用全角形式。

正确：

> 乔布斯说过：“Stay hungry, stay foolish.”

错误：

> 乔布斯说过：“Stay hungry，stay foolish。”

### 标点与空格配合

- 中文标点与相邻文字之间不加空格。
- 英文句子内部按英文规则使用空格。
- 中文括号用于中文句子中的补充说明，即使括号内是英文缩写。
- 不要把代码或 URL 内部的半角标点替换为全角标点。

## 中文链接

中文正文中的 Markdown 链接与前后中文之间建议增加空格，使链接边界清晰。

建议：

> 访问网站的最新动态，请 [点击这里](#) 进行订阅。

不建议：

> 访问网站的最新动态，请[点击这里](#)进行订阅。

链接位于句首、句末、标题、表格或本来就有标点分隔时，不要强行增加多余空格。

## 简繁体与地区用词

- 默认使用简体中文，除非用户或现有文档明确采用繁体中文。
- 默认采用中国大陆常用词，例如“程序”“软件”“硬盘”。
- 不要在同一篇文档中无意混用简体字和繁体字。
- 专有名词、引用、书名和用户指定文本可以保留原写法。
- 转换地区词汇时先确认语义，不要只做逐字替换。

## 最终检查

- 专有名词大小写一致且没有误改标识符。
- 中文、英文、数字和单位之间的空格一致。
- 中文句子使用中文标点，完整英文句子使用英文标点。
- 代码块、行内代码、URL、路径和 Markdown 链接目标保持不变。
- 简繁体和地区用词符合文档上下文。
- 仅修正排版时，不改变事实、语气、标题结构或列表层级；重写时的结构调整符合用户授权范围。
